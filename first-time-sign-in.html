Quick Version

  1. Open https://bsn.cloud/.
  2. Use the email address that was invited to BrightSign / BSN.Cloud.
  3. Complete account creation or password setup if prompted.
  4. Verify email if BrightSign asks for verification.
  5. Sign in.
  6. Select the correct BSN.Cloud network.
  7. Confirm the needed menu areas are visible: Dashboard/Home, Network/Players, Content/Presentations/Schedule, or Admin depending on role.
  8. If the network is missing, ask the BrightSign admin to confirm invite, email spelling, user role, and network assignment.

Before You Start

You need:

  • Internet access.
  • The email address that was invited.
  • Access to that email inbox.
  • A supported browser such as Chrome or Edge.
  • The expected BSN.Cloud network name, if available.
  • The expected role: Administrator, Creator, Network Manager, Helpdesk/NOC, Viewer, etc.
Important: Use the exact email address that received the invitation. If the invite was sent to a different address or alias, the user may sign in successfully but not see the company network.

First-Time Sign-In Steps

Step 1 — Open BSN.Cloud

Open a browser and go to https://bsn.cloud/.

Step 2 — Choose Sign In

Click the sign-in option. If prompted to choose a product area or portal, continue with the BSN.Cloud / BrightAuthor:connected sign-in path.

Step 3 — Enter the invited email address

Use the email address where the BrightSign invite was sent. Do not use a personal email or alternate work alias unless that is the invited address.

Step 4 — Complete account setup

If this is the first BrightSign account, the user may be asked to create a password, confirm name, accept terms, and verify email. If the user already has an account, they may only need to enter the password.

Step 5 — Check email for verification or invitation

  1. Open the email inbox.
  2. Search for BrightSign, BSN.Cloud, or bsn.cloud.
  3. Click the verification/invitation link.
  4. Return to https://bsn.cloud/ and sign in again if needed.

Step 6 — Select the correct network

After sign-in, confirm the correct BSN.Cloud network is selected. If the user belongs to more than one network, use the network selector.

Step 7 — Confirm access

Verify the user can see the areas required for their role: Dashboard/Home, Network/Players, Groups, Content/Library, Presentations, Schedule, or Admin. Missing sections may be normal for limited roles.

Permission Checklist for the Admin

User typeSuggested access
Executive / ViewerView-only access to network/player status and reports, if available.
NOC / Support TechPlayer status, diagnostics, groups, logs, and limited operational tools.
Content ManagerContent library, presentations, schedules, publishing access.
Service AdminNetwork/player management, groups, setup/provisioning, diagnostics.
Full AdminAdmin/user management, network settings, provisioning, billing/subscription areas if needed.

Principle: give the least access needed for the job.

Common First-Time Problems

User signs in but does not see the company network

Likely causes: wrong email, invite sent to another alias, invite not accepted, user not assigned to network, or signed into an old/personal BrightSign account.

User never received the invite or verification email

Check Junk/Spam/Quarantine. Search for BrightSign, BSN.Cloud, or bsn.cloud. Ask the admin to resend the invite and confirm email spelling.

User can log in but cannot see Players, Content, Schedule, or Admin

The assigned permissions may be too limited. Confirm the user's role and network assignment.

Browser keeps opening the wrong account

Sign out, open an InPrivate/Incognito window, go to https://bsn.cloud/, and sign in with the invited email.

First Login Validation

After signing in, have the new user confirm:

  1. What email address are you signed in with?
  2. What BSN.Cloud network name do you see?
  3. Can you see Network or Players?
  4. Can you see the expected player group?
  5. Can you see Content, Presentation, or Schedule if your role requires it?
  6. Are any expected menu items missing?

UberDisplays Internal Notes

  • NOC users need player status, diagnostics, groups, and logs.
  • Content users need content/presentation/schedule publishing.
  • Service administrators need setup/provisioning/player management.
  • Full admin access should be limited.

Do not give broad admin rights just because someone needs to view player status.
